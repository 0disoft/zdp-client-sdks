# SDK migration v0.15.3 to v0.16.0

## Breaking changes

### Referral creation request

`core.referral.uses.create`의 request 계약에서 `campaign_ref`와 `referred_account_ref`가 제거됐다. 두 값은 서버가 인증된 주체와 활성 campaign 정책에서 결정하므로 클라이언트가 전송하면 안 된다.

기존 호출은 다음과 같다.

```ts
await client.raw.call(
  'core.referral.uses.create',
  {
    body: {
      referral_code: referralCode,
      campaign_ref: campaignRef,
      referred_account_ref: accountRef
    }
  },
  { idempotencyKey: crypto.randomUUID() }
);
```

`v0.16.0`에서는 generated domain method와 축소된 payload를 사용한다.

```ts
await client.core.referral.uses.create(
  {
    referral_code: referralCode
  },
  {
    idempotencyKey: crypto.randomUUID()
  }
);
```

직접 만든 request interface, fixture, mock handler에서도 제거된 두 필드를 삭제해야 한다. 서버가 더 이상 받지 않는 필드를 `as` cast로 되살리지 않는다.

### Error handling

`v0.16.0`은 operator context와 support intake operation을 추가하면서 공개 error code 집합을 확장했다. `switch (error.code)`를 exhaustive하게 처리하는 소비자는 default branch로 뭉개지 말고 새 code를 사용자 재시도, 인증 복구, 운영자 권한 부족, 지원 요청 상태 충돌로 구분한다.

```ts
try {
  await client.support.cases.replies.create(input, options);
} catch (error) {
  if (!(error instanceof ZdpApiError)) throw error;

  switch (error.code) {
    case 'authentication_failed':
      return reopenAuthentication();
    case 'scope_access_denied':
      return showOperatorPermissionError();
    case 'source_version_conflict':
      return reloadCaseBeforeRetry();
    default:
      return reportUnexpectedApiError(error);
  }
}
```

### Package consumption

패키지는 이제 `src/**/*.ts`가 아니라 compiled ESM과 declaration을 `dist/`에서 공개한다. public package export만 사용한 코드는 import 경로를 바꿀 필요가 없다. `zdp-client-sdks/src/**`나 저장소 상대 경로를 직접 import한 코드는 지원 대상이 아니므로 package root, `/typed-fetch`, `/typed-fetch/api-operations`, `/upload` 중 하나로 옮긴다.

마이그레이션 뒤에는 TypeScript build와 packed consumer smoke를 실행한다.

```bash
bun install --frozen-lockfile
bun run check
bun run smoke:package
```

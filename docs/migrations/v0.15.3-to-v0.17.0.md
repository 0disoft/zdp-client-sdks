# SDK migration v0.15.3 to v0.17.0

## Breaking changes

### Referral creation request

`core.referral.uses.create` 요청에서 `campaign_ref`와 `referred_account_ref`가 제거됐다. 두 값은 서버가 인증된 주체와 활성 campaign 정책으로 결정하므로, 직접 만든 request interface와 fixture에서도 삭제해야 한다.

```ts
await client.core.referral.uses.create(
  { referral_code: referralCode },
  { idempotencyKey: crypto.randomUUID() }
);
```

제거된 필드를 type cast로 다시 전송하지 않는다. 구버전 mock server가 두 필드를 요구한다면 SDK payload를 되돌리는 대신 mock을 현재 API 계약에 맞춘다.

### Abuse challenge verification reference

`AbuseChallengeRedeemResponse.verification_ref`는 일회성 검증 흐름에만 전달하는 secret material이다. 응답 객체 전체를 로그, telemetry, analytics, local storage 또는 durable cache에 저장하던 소비자는 해당 필드를 반드시 제외해야 한다. 검증 reference는 정해진 다음 요청에만 전달하고 재사용하지 않는다.

### Account settings overview

`v0.17.0`은 인증된 현재 세션의 공통 설정 요약을 읽는 `core.account.settings_overview.get`을 추가한다. 이 operation은 request body나 actor/workspace 식별자를 받지 않는다.

```ts
const overview = await client.core.account.settingsOverview.get();
```

클라이언트가 `actor_ref`, `workspace_ref` 또는 권한 값을 만들어 요청에 넣지 않는다. 서버가 현재 세션에서 결정한 account, workspace, session, connected products와 notification preferences만 렌더링한다.

마이그레이션 뒤에는 TypeScript build, SDK compatibility gate와 packed consumer smoke를 실행한다. 공개 package export만 사용하고 저장소의 `src/**` 상대 경로를 직접 import하지 않는다.
